II. Software Design Document
1. High Level Design
1.1 Software Architecture
The system follows a layered MVC architecture on top of the Jakarta Servlet API (Java 21, deployed on Apache Tomcat). The browser talks to Controller servlets under com.cinema.controller (e.g. LoginController, BookingController, MovieController, PromotionServlet); AuthFilter and EncodingFilter (com.cinema.filter) intercept every request first to enforce session authentication/authorization and UTF-8 encoding. Controllers call the Service/DAO layer (com.cinema.dao) for business logic and JDBC data access, which in turn populates Model beans (com.cinema.model) and reads/writes the CinemaBookingDB SQL Server database through DBContext/DBUtils (com.cinema.util). Controllers forward request-scoped data to JSP views under /view for rendering. A background ServletContextListener, PromotionStatusScheduler (com.cinema.listener), periodically recomputes Promotion.Status (upcoming / active / expired) independently of any user request.
Figure 1.1 — System Architecture
1.2 Package Diagram
Source code is organized under the com.cinema root package. Controllers depend on DAOs and Models; DAOs depend on the util package for the JDBC connection and password hashing helpers; the filter package intercepts controller calls; the listener package triggers scheduled DAO calls outside the request/response cycle; and the exception package holds the custom exceptions (ValidationException, NotFoundException, ConflictException) that controllers throw and catch to return proper HTTP/JSP error responses.

2. State Transition Diagrams
This section documents the lifecycle of the three entities whose state changes drive the main business rules of the system: a booked Seat/Ticket, a Promotion, and an Invoice's payment status. Each diagram lists the triggering event and, where applicable, the controller/DAO method or database CHECK constraint that enforces it.
2.1 Seat / Ticket Booking State
A seat moves from Available to Held while it sits in a customer's BookingCart, to Booked once BookingController/TicketDAO.createManualBooking() has written the Invoice and Ticket rows, and to Sold once Invoice.PaymentStatus becomes 'Paid'. CheckedIn is reached when staff scan the ticket's QR Code at the door (Ticket.IsCheckedIn = 1).
Figure 2.1 — Seat / Ticket booking state diagram
2.2 Promotion Status State
Promotion.Status is a derived field constrained to 'upcoming' / 'active' / 'expired' / 'inactive' by a database CHECK constraint. PromotionServlet updates it directly in response to admin actions (create, deactivate, reactivate, activate-early); the background PromotionStatusScheduler listener re-evaluates every promotion's dates on a timer to move upcoming -> active and active -> expired even without any admin action.
Figure 2.2 — Promotion status state diagram
2.3 Invoice Payment Status State
Invoice.PaymentStatus is constrained to 'Pending' / 'Paid' / 'Failed' / 'Refunded' by a database CHECK constraint. It starts at 'Pending' the moment TicketDAO inserts the Invoice row, and is updated once a payment result (cashier confirmation, gateway callback, or admin cancellation) is known.
Figure 2.3 — Invoice payment status state diagram
3. Detailed Design
3.1 Authentication & Account Management
Covers login, registration and password recovery. LoginController and RegisterController (com.cinema.controller) delegate credential checks and persistence to AccountDAO, which uses PasswordHash to hash/verify passwords. AuthFilter reads the session-scoped Account on every subsequent request to enforce role-based access.

3.2 Ticket Booking & Payment
Covers seat selection, food add-ons and checkout. BookingController keeps the in-progress selection in a session-scoped BookingCart, backed by BookingScheduleDAO and BookingSeatDAO for read queries. At checkout, TicketDAO.createManualBooking() runs a single JDBC transaction that inserts the Invoice, one Ticket per selected seat, and increments Promotion.UsedCount when a discount code was applied.

3.4 Promotion Management
Covers creating and maintaining discount codes. PromotionServlet is a single servlet that fans out to private handleCreate/handleUpdate/handleDeactivate/handleReactivate methods based on the 'action' request parameter, using nested PromotionRequestDTO / PromotionResponseDTO classes to shape request and response data; PromotionDAO performs the persistence.
